# Homepage exhibition and online-room content

- Hero: published current/upcoming exhibitions appear automatically. Project events/news still require Published and Main Featured. Virtual highlight entries are no longer duplicated in the hero.
- Current exhibition rows: every published current exhibition gets poster, title, artist, dates and venue on the left, up to four linked published virtual-gallery works on the right. Existing artwork image/title/artist/year fields are reused; no homepage upload is required. Shared exact image references are deduplicated inside an exhibition. Clicking a work uses the existing #art-{id} position link.
- Only published galleries contribute works. Publishing a physical exhibition alone does not expose a draft online gallery or its works. Without published works, show an image-preparation message instead of repeating the poster as an artwork.
- Online Viewing Rooms: choose up to three public rooms randomly on page entry, retain that choice while subscriptions update, and use room identity rather than artist-profile cards. Closed physical exhibitions can still have published online rooms. Prefer distinct work thumbnails where rooms share content. No available room means hide the section; failed reads are not silently interpreted as empty.
- Queries and media: existing Firebase default project and private/public R2 authorization remain unchanged. Relevant room artwork reads use a four-item ordered limit; only the selected homepage image references are hydrated, with shared-request caching and blob URL cleanup. Returning via browser page cache reloads the homepage previews.
- Local QA uses clearly labeled demo exhibitions and artworks. Demo fixtures are never written to Firebase. Production content depends on actual staff publication and available public room images.
