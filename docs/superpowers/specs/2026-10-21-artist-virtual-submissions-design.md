# 작가 업로드·승인 및 버추얼 갤러리 관람 개선 설계

작성일: 2026-10-21 · 상태: 사용자 승인 후 구현

## 목표

1. 작가가 초대 링크로 자기 버추얼 갤러리를 직접 업로드하고, 언프레임 직원이 승인해야 공개된다. 관리자 권한(`staffEmails`)은 늘리지 않는다.
2. 승인되지 않은 업로드는 마지막 수정 후 10일이 지나면 접근이 막히고, 직원이 `/admin`에 들어올 때 삭제된다.
3. 공개 갤러리의 관람 경험을 개선한다(1~3단계).

데모 모드와 실제 Firebase 운영의 구분, 기존 `unframe-main` 프로젝트·웹 앱, 서비스 계정 키 미사용 원칙을 유지한다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 작가 자격 | 직원이 만든 초대 링크 + Google 로그인. 처음 로그인한 계정에 귀속 |
| 초대 이메일 | 선택. 입력하면 그 이메일로만 귀속 가능 |
| 만료 | 마지막 수정(작가 저장·직원 연장) 후 10일, 서버 시간 기준 |
| 삭제 방식 | 만료 즉시 규칙으로 접근 차단, 실제 삭제는 직원 `/admin` 접속 시 |
| 승인 후 수정 | 작가가 수정본을 만들고 다시 승인. 수정본만 만료 대상 |

## 1. 데이터 구조

### `virtualSubmissions/{submissionId}`

`submissionId`는 브라우저 `crypto.getRandomValues`로 만든 22자 base62 값(추측 불가)이며 초대 링크 `/artist-studio/{submissionId}`에 쓰인다.

| 필드 | 형식 | 작성자 |
|---|---|---|
| `exhibitionId` | 전시 ID | 생성 시 고정 |
| `exhibitionTitle` | 문자열 ≤200 (비공개 전시도 작가 화면에 이름 표시) | 생성 시 고정 |
| `artistName` | 문자열 1~300 | 생성 시 고정 |
| `invitedEmail` | `''` 또는 소문자 이메일 | 생성 시 고정 |
| `ownerEmail` | `''`(미귀속) 또는 귀속된 Google 이메일 | 최초 로그인 시 1회 |
| `targetGalleryId` | `''`(신규) 또는 수정 대상 갤러리 ID | 생성 시 고정 |
| `status` | `invited` · `draft` · `submitted` · `rejected` | 아래 전이 규칙 |
| `reviewNote` | 문자열 ≤1000 (반려 사유) | 직원 |
| `settings` | `{theme, wallColor, lighting, ceiling}` (기존 허용 값) | 작가·직원 |
| `createdAt` | timestamp | 생성 시 |
| `expiresAt` | timestamp = 마지막 쓰기 시각 + 10일 | 모든 쓰기에서 규칙이 강제 |

작품: `virtualSubmissions/{submissionId}/artworks/{artId}` — 기존 `validArtwork`와 같은 필드·한도(작품명·작가·세로·가로·벽면·형태 필수, 연도·재료·설명 등 선택). 이미지 경로는 `virtualSubmissions/{submissionId}/{artId}/{uuid}.{ext}`이며, 수정본에서는 대상 갤러리의 기존 경로 `virtualGalleries/{targetGalleryId}/{artId}/…`도 허용한다.

### 공개 갤러리 변경

`virtualGalleries/{galleryId}`에 선택 필드 `artistEmail`을 추가한다(승인 시 기록). 이 계정은 자기 갤러리 문서·작품을 공개 여부와 관계없이 읽을 수 있고(수정본 작성용), 수정본을 만들 수 있다. 쓰기 권한은 여전히 직원만 가진다.

## 2. 보안 규칙 (Firestore)

- **만료:** 작가 관련 모든 읽기·쓰기는 `resource.data.expiresAt > request.time`일 때만 허용한다. 모든 쓰기(직원 포함)는 `request.resource.data.expiresAt == request.time + duration.value(10,'d')`여야 한다.
- **초대 열람:** 로그인 전 링크 첫 화면을 위해 `get`만 허용한다(목록 조회 불가). 조건은 미귀속(`ownerEmail==''`)이고 만료 전인 문서다.
- **귀속(claim):** 검증된 Google 로그인이면서 `ownerEmail==''`일 때, `ownerEmail`을 자기 이메일로, `status`를 `draft`로 바꾸는 업데이트만 허용한다. `invitedEmail`이 있으면 그 이메일과 같아야 한다.
- **작가 편집:** `ownerEmail == request.auth.token.email`이고 상태가 `draft`/`rejected`일 때 `settings`, `status`, `expiresAt`만 바꿀 수 있다. 상태 전이는 `draft|rejected → submitted`와 `submitted → draft`(요청 취소)만 허용한다. `submitted` 상태에서는 상태 되돌리기 외의 수정을 막는다.
- **작가 작품 쓰기:** 부모 제출함의 주인이고, 편집 가능 상태이며, 만료 전이어야 한다. 같은 일괄 쓰기에서 부모의 `expiresAt`도 갱신되어야 한다(`getAfter`). 그래서 작품을 저장할 때마다 기한이 연장된다.
- **수정본 생성:** 작가가 직접 만들 수 있다. 조건은 대상 갤러리의 `artistEmail`이 자기 이메일과 같고, `ownerEmail`이 자기 이메일이며, `status`가 `draft`인 것이다.
- **직원:** 초대 생성, 반려(`reviewNote`), 기한 연장, 삭제를 할 수 있다. 읽기는 만료 여부와 관계없이 가능하다(정리용).
- **작가가 할 수 없는 것:** 공개 여부 변경, `virtualGalleries` 쓰기, 다른 제출함 목록 조회.

## 3. 이미지 서버 (Cloudflare Worker)

- 경로 `virtualSubmissions/{id}/{artId}/{uuid}.{ext}`를 추가한다.
- **PUT/GET/DELETE:** 직원이거나 제출함 주인일 때 허용한다. 주인 확인은 작가 토큰으로 제출함 문서를 읽는 방식이다. 규칙상 만료되거나 남의 문서면 읽히지 않는다. 그 위에 `ownerEmail == 토큰 이메일`을 확인하고, 쓰기는 편집 가능 상태일 때만 허용한다.
- **업로드 남용 방지:** 제출함 하나당 R2 객체를 최대 60개로 제한한다(prefix 목록 확인). 기존 10MB 제한과 파일 헤더 검사는 유지한다.
- **비공개 갤러리 이미지:** 수정본 작성 시 작가가 자기 갤러리 이미지를 볼 수 있도록, 문서의 `artistEmail`이 토큰 이메일과 같으면 GET을 허용한다.
- **새 기능 `POST /copy` (직원 전용):** 승인 시 제출함 이미지를 `virtualGalleries/{galleryId}/{artId}/{uuid}.{ext}`로 복사한다. 원본은 제출함 경로만, 대상은 갤러리 경로만 허용한다.

## 4. 화면 흐름

### 관리자 (`/admin` → 전시 → 버추얼 갤러리 → 작가 초대)

- **작가 초대하기:** 작가명은 필수, 이메일은 선택이다.
- **초대 카드:** **링크 복사**, **안내문 복사**, **메일로 보내기**(이메일이 있을 때) 버튼이 있다.
  - 안내문에는 작가명, 전시명, 링크, 기한, 절차, 그리고 "처음 로그인한 Google 계정에 권한이 연결됩니다. 앞으로 사용할 본인 계정으로 로그인하고 링크는 공유하지 마세요"가 들어간다.
- **초대 목록:** 상태와 남은 일수를 표시하고, 2일 이하로 남으면 경고 색을 쓴다. **기한 연장**과 **초대 취소**가 있다.
- **심사 대기 배지:** 관리자 첫 화면에 표시한다.
- **심사 화면:** 3D 미리보기와 작품 목록을 보여준다. 수정본이면 작품마다 변경·추가·삭제 표시가 붙는다. 버튼은 **승인 후 공개**, **승인만**, **반려(사유)** 세 가지다.
  - **승인 절차:** 이미지 복사 → 갤러리 설정·작품 쓰기 → 수정본에서 빠진 작품·이미지 삭제 → 제출함·제출함 이미지 삭제.
  - 단계 중간에 실패하면 제출함을 남겨 두고 오류를 안내한다. 다시 승인해도 결과가 같다(멱등).
- **만료 정리:** `/admin`에 들어오면 만료된 제출함(`expiresAt < now`)을 조회해 이미지·작품·문서를 삭제하고, 결과를 알림으로 한 번 표시한다.

### 작가 (`/artist-studio/{id}`)

1. **링크 첫 화면:** 작가명, 전시명, 마감일과 함께 계정 귀속 안내 상자, 절차, 자동 삭제 안내, **업로드하기** 버튼이 있다. 버튼을 누르면 Google 로그인 후 귀속된다.
2. **편집 화면**
   - 상단에 상태, 로그인 계정, **3D 미리보기**, **심사 요청**이 있다.
   - 남은 기간 띠를 항상 표시한다.
   - 작품 목록과 입력란: 이미지, 작품명, 세로·가로(cm), 벽면, 형태, 연도, 재료, 설명(선택).
   - 공간 설정은 바닥, 벽 색, 조명, 천장이다.
   - 작품은 최대 24점, 벽당 8점이고, 실측 배치 검증은 기존과 같다.
3. **심사 요청 후:** 편집이 잠기고 **요청 취소**만 할 수 있다. 반려되면 사유가 표시되고 다시 편집할 수 있다.
4. **승인 후:** 제출함이 삭제되므로 링크를 열면 "승인되어 공개되었습니다 / 처리된 초대입니다"가 표시된다. 같은 계정으로 들어오면 내 갤러리 목록과 **수정본 만들기**가 보인다.
5. **오류 안내:** 만료되었거나 다른 계정으로 접근하면 각각에 맞는 안내와 언프레임 문의 안내를 보여준다.

### 3D 미리보기

작가와 직원 모두 `/virtual-gallery/submission/{id}?preview=1`로 제출함 데이터를 기존 렌더러에 그대로 넘겨 확인한다.

## 5. 관람 개선

1단계
- **화면 정리:** 입장 후 제목 카드를 축소하고, 버튼은 메뉴 하나로 묶는다. 4초 동안 조작이 없으면 화면 위 요소를 흐리게 하고, 움직이면 다시 표시한다.
- **안내 문구:** 터치 기기에서는 드래그와 이동 버튼 안내를 보여주고, 키보드 안내는 숨긴다.
- **캡션:** 벽 캡션의 글자를 더 크게 그리고 작품에 붙인다.
- **가이드 투어:** 상세창 없이 작품 앞에 서서 감상하는 모드로 바꾼다. 하단 막대에 `3 / 12`, 이전, 다음, 상세 보기, 종료를 두고, 마지막 작품에서 끝난다.

2단계
- **작품 주소:** `#art-{id}`로 열면 그 작품 앞에서 시작한다. 상세창은 방문 기록에 쌓이므로, 뒤로가기를 누르면 닫힌다.
- **벽 바로가기:** 메뉴에 전면, 좌측, 우측 벽 이동을 둔다.
- **로딩 진행률:** 작품 이미지를 불러오는 진행률을 표시하고, 완료되면 입장 버튼을 활성화한다. 일부가 실패해도 입장할 수 있다.
- **이미지 확대:** 상세 이미지를 탭하거나 클릭하면 2배로 확대하고, 드래그로 이동할 수 있다.

3단계
- **코드 분리:** `virtual-room.js`를 입력, 투어, 화면 요소(HUD), 화질 설정 모듈로 나눈다. 동작은 그대로 유지한다.
- **화질 단계:** 저·중·고 단계를 둔다. 기기 메모리, 코어 수, 화면 크기로 단계를 정하고, 첫 3초의 프레임 속도가 낮으면 한 단계 내린다. 단계에 따라 그림자, 해상도 배율, 식재 수가 달라진다.
- **Three.js 버전 전환:** 마지막에 시도한다. 렌더링, 색감, 성능을 비교해서 문제가 있으면 r128을 유지하고 그 사실을 보고한다.

**제외:** 작품 오디오 해설. 음원 업로드 형식, 이미지 서버 확장, 저작권 확인이 필요해서 별도 작업으로 진행한다.

## 6. 데모 모드

제출함, 초대, 작가 로그인, 승인, 만료 정리 모두 localStorage에서 동작한다. 작가 로그인은 "샘플 작가 계정"으로 시뮬레이션한다. 실제 Firebase나 R2에는 쓰지 않는다.

## 7. 검증

- **Node 테스트:** 제출 모델(상태 전이, 만료 계산, 안내문 생성), 작가 화면 검증, Worker 권한(주인·만료·남의 제출함·복사·60개 제한), 투어·딥링크 로직.
- **Firestore 에뮬레이터 규칙 테스트:**
  - 귀속, 이메일 제한, 만료 후 거부, 상태 전이, 작품 쓰기 때 부모 기한 갱신 필수.
  - 작가의 공개 갤러리 쓰기 거부, 수정본 생성 조건.
- **마무리 확인:** `npm run check`, `npm test`, `npm run build`를 실행하고, 브라우저에서 데모 흐름(초대 → 업로드 → 심사 → 승인 → 공개, 만료 정리)과 데스크톱·모바일 관람을 확인한다.
- **배포:** 규칙과 Worker 배포는 사용자 확인 후 진행한다.
