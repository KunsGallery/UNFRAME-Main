# 공개 페이지 영문판 설계

작성일: 2026-10-27 · 상태: 방향 승인, 문서 검토 대기

## 목표

관람객이 보는 공개 페이지를 영어로도 볼 수 있게 한다. 모든 공개 페이지 우상단의 `KO / EN` 드롭다운으로 언어를 바꾼다. 관리자 화면과 작가 업로드 화면은 한국어 그대로 둔다.

**성공 기준**
- `/en/`으로 시작하는 주소에서 고정 문구가 처음부터 영어로 보인다. 한국어가 깜빡이지 않는다.
- 영문 입력이 없는 내용은 한국어로 보이고, 화면이 깨지지 않는다.
- 문구를 고칠 때 한 곳만 고치면 된다.

## 범위

| 포함 | 제외 |
|---|---|
| 메인(`index`), 전시 목록(`exhibition`), 전시 상세(`detail`), 프로젝트(`project`, `project-scroll`, `project-lab`), 소개(`about`), 버추얼 갤러리(`virtual-gallery`), 상품 미리보기(`shop-preview`) | 관리자(`admin`), 작가 업로드(`artist-studio`), 아임웹 쇼핑몰, 자동 번역 서비스, 세 번째 언어 |

## 주소

- 한국어는 지금 주소를 그대로 쓴다. 영문은 같은 주소 앞에 `/en`을 붙인다.
  - 예: `/exhibition/abc` ↔ `/en/exhibition/abc`, `/virtual-gallery/xyz` ↔ `/en/virtual-gallery/xyz`
- 기존 경로 연결 규칙(`netlify.toml`과 빌드가 만드는 `_redirects`)마다 `/en` 버전을 추가한다.
- 각 페이지 `<head>`에 서로를 가리키는 `hreflang` 링크(`ko`, `en`)를 넣어 검색엔진이 두 판을 짝으로 인식하게 한다.

## 고정 문구

**번역 사전**
- `site/js/i18n.js` 한 파일에 키별로 한국어와 영어 문구를 둔다(예: `nav.exhibitions: {ko:'전시', en:'Exhibitions'}`).
- 이 파일이 문구의 유일한 출처다.

**HTML 문구**
- 공개 페이지 HTML의 고정 문구 요소에 `data-i18n="키"`를 붙인다. `alt`, `aria-label`, `placeholder`, `title`은 `data-i18n-attr="속성:키"`로 표시한다.
- 빌드(`scripts/build.mjs`)가 `dist/en/*.html`을 만들 때 다음을 바꿔 넣는다.
  - 표시된 문구를 영어로 교체
  - `<html lang="en">`
  - 메타 제목·설명
  - 사이트 내부 링크의 `/en` 접두어
- 한국어 페이지는 지금 파일 그대로 배포한다.

**스크립트 문구**
- 버튼 이름, 상태, 오류 안내, 빈 목록 안내처럼 스크립트가 화면에 쓰는 문구는 `t('키')`로 바꾼다.
- 언어는 주소가 `/en/`으로 시작하는지로 정한다(`lang()`).
- 내부 링크는 `localHref(path)`로 만들어 영문판에서 `/en`이 붙게 한다.

**날짜와 상태**
- 날짜는 지금 형식(`2026.10.01 — 11.15`)을 두 언어에서 같이 쓰고, 요일 등 한국어 표기만 영어로 바꾼다.
- 전시 상태는 기존 `stateEnglish`(NOW SHOWING, UPCOMING, ARCHIVE)를 그대로 쓴다.
- 가격은 입력한 그대로(원화) 보여준다.

**번역 작업 방식**
- 영어 초안은 구현하면서 작성하고, 사용자가 문구 목록을 검토해 고친다.
- 영문 페이지에 표시하지 않은 한국어 고정 문구가 남으면 테스트가 실패한다(아래 검증 참고).

## 언어 드롭다운

- 공개 페이지 우상단 헤더에 `KO / EN` 선택을 둔다. 모바일에서는 메뉴 안에 둔다.
- 바꾸면 보던 페이지의 다른 언어판으로 이동한다. 주소의 경로, 쿼리, `#art-` 해시를 유지한다.
- 고른 언어는 브라우저(`localStorage`)에 기억한다. 언어 없는 주소(`/`)로 다시 왔을 때 기억된 언어가 영어면 `/en/`으로 보낸다.
- 처음 방문에서 브라우저 언어만 보고 자동으로 옮기지는 않는다.

## 직접 입력하는 내용

기존 `titleEn` 방식처럼 같은 문서에 `En`이 붙은 선택 필드를 둔다.

| 문서 | 새 필드 |
|---|---|
| 전시(`exhibitions`) | `titleEn`, `summaryEn`, `descriptionEn`, `locationEn`, `hoursEn`, `admissionEn` |
| 하이라이트·프로젝트(`highlights`) | `titleEn`, `summaryEn` |
| 버추얼 갤러리 설정(`virtualGalleries`) | `titleEn`, `subtitleEn`, `artistNoteEn` |
| 작품(`artworks`) | `descriptionEn`, `mediumEn` (`titleEn`은 이미 있음) |

- **보여주는 규칙:** `localized(item, 'title')`은 영문판에서 `titleEn`이 비어 있지 않으면 그것을, 아니면 한국어 `title`을 돌려준다. 작가명과 주소는 번역하지 않는다.
- **글자 수 제한:** 영문 필드는 같은 이름의 한국어 필드와 같다.
- **관리자 화면:**
  - 해당 편집 화면마다 한국어 칸 아래 "영문 (선택)" 칸을 둔다. 긴 설명은 접어 두었다 펼친다.
  - 화면 안내는 한국어 그대로다.
- **작가 업로드:**
  - 작가 업로드 화면과 작가 제출함에는 영문 필드를 추가하지 않는다.
  - 승인 뒤 관리자가 갤러리 작품에서 영문을 입력한다.
- **Firestore 규칙:**
  - 각 문서의 허용 필드(`hasOnly`)에 새 필드를 추가하고 문자열·길이를 검사한다.
  - 제출함(`virtualSubmissions`) 규칙은 바꾸지 않는다.
- **데모 모드:** 샘플 데이터에 영문 필드 몇 개를 넣어 영문판과 대체 동작을 확인할 수 있게 한다. Firebase 모드와의 구분은 그대로 둔다.

## 공유 카드와 버추얼 갤러리

- **작품 공유 카드:** 영문판에서 만들면 카드 라벨과 작품 정보에 영문 필드를 쓴다.
- **버추얼 갤러리:** 입장 안내, 메뉴, 투어, 작품 정보 창, 조작 안내를 번역한다. 3D 공간의 벽 캡션은 작품 정보와 같은 대체 규칙을 따른다.

## 반영 순서

Firestore 규칙 → 사이트 머지. 화면이 새 필드를 저장하기 전에 규칙이 먼저 받아들여야 한다. Worker는 바꾸지 않는다.

## 검증

- **단위 테스트**
  - `localized` 대체 규칙
  - `localHref`와 언어 전환 주소 변환(경로, 쿼리, 해시 유지)
  - 사전의 모든 키에 `ko`와 `en`이 있는지
  - 코드에서 쓰는 키가 사전에 모두 있는지
- **빌드 테스트**
  - `dist/en/`에 범위의 모든 페이지가 생기는지
  - 영문 HTML의 고정 텍스트에 한글이 남지 않았는지(입력 내용이 들어갈 자리는 제외)
  - `lang="en"`, `hreflang`, 내부 링크의 `/en` 접두어
- **규칙 에뮬레이터:** 새 필드의 허용, 형식·길이 거부, 제출함 규칙이 그대로인지.
- **브라우저(데모):** 각 공개 페이지를 영문으로 열어 드롭다운 전환, 기억, 대체 표시, 버추얼 갤러리 안내, 모바일 메뉴를 확인한다.

## 범위 밖으로 남기는 것

- 작가가 직접 영문 입력
- 세 번째 언어
- 자동 번역
- 관리자·작가 화면 영문화
- 아임웹 쇼핑몰
