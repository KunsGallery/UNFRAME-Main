# UNFRAME 전시 사이트 시작하기

## 현재 완성된 내용

기존 HTML의 전시 목록/아카이브 구조를 확장했습니다. 전시 목록과 상세 페이지, 사진 확대 보기, 검색/연도/현재·예정·아카이브 필터, 직원 관리자, 신규 등록/수정/삭제, 대표 이미지 및 전시 사진 업로드, 사진 순서/캡션, 저장 전 미리보기, 임시 저장/게시, 노출 순서를 제공합니다.

현재 설정은 **샘플 체험 모드**입니다. 제목과 그래픽은 제공된 예시에서 확장한 샘플이고 실제 UNFRAME 전시로 확인된 정보가 아닙니다. 샘플 관리자의 데이터는 해당 브라우저에만 저장됩니다. 이 모드의 관리자 체험 버튼은 보안 로그인 기능이 아닙니다. Firebase 연결 시 자동으로 없어집니다. 실제 데이터베이스에는 샘플을 자동 등록하지 않습니다.

## 로컬에서 확인

`site` 폴더에서 `npm run dev` 실행 후 http://127.0.0.1:4173 방문. 관리자 주소는 /admin 입니다.

검사: `npm run check`, `npm test`.
배포 폴더 생성: `npm run build`. 결과는 site/dist/ 입니다.

## Firebase 설정

1. 사용할 Firebase 프로젝트와 웹 앱을 선택합니다. 웹 앱의 firebaseConfig를 `site/config.js`의 firebase 항목에 입력합니다. 이 웹 앱 설정은 브라우저에 공개되는 정상 설정이며 서비스 계정 비밀키를 넣으면 안 됩니다.
2. Authentication → Sign-in method에서 Google을 켭니다. 승인 도메인에 실제 Netlify 배포 도메인, exhibition.unframe.kr을 등록합니다. localhost에서 검증할 경우 localhost 및 127.0.0.1도 등록합니다.
3. Firestore 기본 데이터베이스와 Storage를 생성합니다. 서비스 이용 가능 여부와 결제 요구사항은 Firebase 콘솔에서 확인합니다.
4. Firebase CLI에서 프로젝트를 선택한 후 `site` 폴더에서 `firebase deploy --only firestore:rules,storage`로 제공된 규칙을 배포합니다. Storage 규칙이 Firestore를 읽도록 필요한 서비스 권한 설정을 확인합니다. 기존 프로젝트라면 기존 규칙을 백업하고 다른 사이트 컬렉션과 충돌하지 않도록 병합해야 합니다. 이 규칙은 exhibitions/staff 외 데이터를 기본 차단합니다.
5. Storage 버킷의 CORS를 `site/cors.json` 기준으로 설정합니다. 실제 Netlify 미리보기 도메인도 origin 목록에 추가합니다. Cloud SDK 사용 시 `gcloud storage buckets update gs://버킷이름 --cors-file=cors.json`을 사용합니다. 이미지 읽기는 공개 다운로드 토큰 대신 보안 규칙이 적용되는 getBlob으로 수행하므로 CORS가 필요합니다.
6. mode를 firebase로 변경하고 다시 빌드/배포합니다. Firebase 연결 오류가 발생하면 샘플 모드로 자동 전환하지 않고 오류를 표시합니다.

## 관리자 승인

단순히 Google 로그인이 성공해도 관리자 권한은 생기지 않습니다.

1. 관리자 주소에서 본인 또는 직원이 Google 로그인을 한번 수행합니다. 승인 전에는 관리자 접근이 차단됩니다.
2. Firebase Authentication 사용자 목록에서 해당 계정의 UID와 정확한 이메일을 확인합니다.
3. Firestore 콘솔에서 `staff` 컬렉션에 문서 ID를 그 UID로 만들고 `email` 문자열에 해당 Google 계정 이메일, `active` 불리언에 true를 넣습니다.
4. 직원이 다시 로그인하면 전시 관리 권한이 적용됩니다. 직원 퇴사/권한 해제 시 해당 문서의 active를 false로 변경합니다.

직원이 앱에서 자기 자신 또는 다른 계정의 권한을 만들거나 변경할 수 없도록 staff 쓰기는 전부 차단했습니다. 승인된 UID·이메일·Google 제공자·이메일 인증 상태를 데이터베이스와 Storage 양쪽에서 확인합니다. 실제 운영 계정으로 승인/미승인/로그아웃 시나리오를 반드시 검증합니다.

## 공개 범위

방문자는 로그인하지 않고 published=true 전시만 조회할 수 있습니다. 비공개 전시는 직원만 읽을 수 있습니다. 업로드된 사진은 공개 전시 문서의 imagePaths에 실제 포함된 파일만 익명으로 읽을 수 있습니다. 삭제/미게시 후에는 공개 읽기 권한이 사라집니다. 이미 방문자 기기에 다운로드된 사진까지 회수할 수는 없습니다.

전시 날짜는 Asia/Seoul 기준입니다. 시작일/종료일 당일에는 현재 전시이며, 날짜가 지난 뒤 목록을 불러오면 아카이브로 분류됩니다.

전시 URL은 고정 ID를 사용해 제목 변경 이후에도 공유 주소를 유지합니다. 주소 이름(slug)은 메타데이터로 보관하며 URL 라우팅에는 사용하지 않습니다.

## Netlify 배포 및 도메인

Git 저장소로 연결할 경우 Base directory = site, Build command = npm run check && npm test && npm run build, Publish directory = dist. 또는 로컬 빌드 후 dist 폴더를 Netlify에 드래그해 배포합니다. dist 안의 _redirects가 상세와 관리자 주소를 처리합니다.

현재는 메인과 전시를 하나로 통합했습니다. 메인은 `/`, 전시 목록은 `/exhibition`, 상세는 `/exhibition/:id`입니다. 서브도메인을 필수로 사용하지 않습니다.

unframe.kr을 최종 Netlify로 이전할 때에는 남은 아임웹 페이지(쇼핑/U.A.U/정책 등)의 이전 또는 별도 연결 주소를 먼저 정해야 합니다. 기존 링크들은 현재 공식 사이트의 주소를 유지하고 있어 메인 도메인을 옮기면 해당 경로도 새 사이트에 구현하거나 실제로 유지되는 별도 아임웹 도메인으로 연결해야 합니다. 아직 도메인 설정은 변경하지 않았습니다.

## 관리 참고

게시를 끄고 저장하면 임시 저장입니다. 실제 게시에는 제목·기간·장소·대표 이미지·전시 소개가 필요합니다. 이미지는 JPG/PNG/WebP, 10MB 이하, 전시 사진은 최대 30장입니다. 샘플 체험에서는 저장 용량 제한 때문에 파일당 2MB 이하입니다.

사진을 업로드한 뒤 저장하지 않고 나가거나 사진을 교체하면 사용하지 않는 파일이 Storage에 남을 수 있습니다. 미사용 파일은 공개 문서에 포함되지 않으면 공개 읽기가 차단됩니다. 주기적인 미사용 파일 정리는 별도 운영 작업입니다. 게시 및 저장을 동시에 여러 직원이 편집하면 마지막 저장이 적용됩니다.

본문은 일반 텍스트와 문단으로 입력합니다. HTML 임베드·동영상·다국어·페이지 배치를 직접 바꾸는 편집기는 이번 범위에 포함되지 않습니다. 상세 메타데이터는 브라우저에서 변경되므로 SNS 미리보기 카드와 검색 최적화용 서버 렌더링은 추후 확장 대상입니다.

## 검증 상태

JavaScript 문법 검사와 날짜 경계/필터/입력 검증/HTML 이스케이프 테스트를 통과했습니다. 로컬 브라우저에서 공개 목록과 필터, 상세, 관리자 임시 저장을 확인했습니다.

실제 Firebase 프로젝트/직원 계정/Netlify 계정이 제공되지 않아 Google 로그인, 원격 업로드, 실제 서버 보안 규칙 적용과 운영 배포는 미검증입니다. 로컬에는 Java가 없어 Firestore 에뮬레이터 보안 테스트를 실행하지 못했습니다. 운영 연결 후 이 검증을 완료해야 합니다.
