# 버추얼 갤러리 운영 안내

전시마다 독립된 버추얼 갤러리를 운영합니다. 제공된 `references/virtual-gallery-original.html`의 숲을 바라보는 3D 공간을 바탕으로, 전시 작품과 공간 설정을 관리자에서 편집합니다.

## 등록과 수정

1. `/admin`에서 승인된 Google 계정으로 로그인하고 관리할 전시의 버추얼 갤러리를 엽니다.
2. 갤러리 제목과 공간 설정을 먼저 저장합니다. 처음 저장한 뒤 작품 추가와 저장된 공간 미리보기가 활성화됩니다.
3. 작품 추가를 눌러 이미지, 작품명, 작가명, 가로·세로 크기, 벽면, 액자와 배치 순서를 입력하고 **작품 저장**을 누릅니다. 영문 작품명, 제작연도, 재료, 가격 또는 문의 안내, 설명과 이미지 설명도 입력할 수 있습니다.
4. 공간 설정을 변경했다면 **공간 설정 저장**을 별도로 누릅니다. 작품 저장과 공간 설정 저장은 서로 다른 작업입니다.
5. **저장된 공간 미리보기**에서 결과를 확인합니다. 이 화면은 저장된 데이터만 보여주며 아직 저장하지 않은 편집 내용은 반영하지 않습니다.

이미지는 JPG·PNG·WebP를 지원하며 실제 운영에서는 파일당 10MB 이하, 샘플 체험에서는 2MB 이하입니다. 정면 촬영한 이미지와 구체적인 이미지 설명을 권장합니다. 업로드 완료 후에도 작품 저장을 눌러야 작품에 반영됩니다.

작품은 관리자 화면에서 최대 24점, 벽면당 최대 8점까지 등록할 수 있습니다. 전면·우측·좌측 벽을 선택하고 벽면 안의 배치 순서를 정합니다. 작품 실제 크기와 간격을 계산해 벽면 안에서 줄을 나누어 배치합니다. 작품 크기는 가로·세로 각각 10~500cm이며, 입력 순서는 세로 → 가로이며, 100cm는 공간에서 1m입니다. 자동 축소는 하지 않습니다. 공간에서 입력한 작품의 가로·세로 비율을 유지합니다. 정면 이미지와 일치하는 치수를 입력해주세요. 작품 형태는 캔버스·블랙 액자·화이트 액자·우드 액자·프레임 없는 종이 중 선택합니다. 새 작품은 캔버스가 기본이며, 테두리 없이 기본 두께 3.5cm의 옆면을 표시합니다. 액자 테두리는 작품 자체의 입력 치수 바깥에 추가됩니다. 현재 벽의 유효 영역은 가로 1,000cm·세로 360cm이며 액자와 간격도 계산합니다. 공간을 넘는 작품·배치는 저장 전에 안내하며, 기존 저장된 배치가 넘는 경우에도 관리자에 경고합니다. 수량 제한은 현재 관리자 클라이언트의 입력 제한입니다.

## 공간과 공개 설정

바닥은 화이트·블랙 헤링본·우드 헤링본·내추럴 우드 중 선택합니다. 벽 색상, 조명 밝기(0.5~1.8), 이동 속도(1~5), 창밖 숲과 마당 표시를 조정할 수 있습니다. 가격 표시를 켜면 가격 또는 문의 안내가 입력된 작품에 해당 정보가 표시됩니다.

공개하려면 작품을 한 점 이상 저장한 뒤 **버추얼 갤러리 공개**를 켜고 공간 설정을 저장합니다. 연결된 전시도 게시해야 일반 방문자가 열람할 수 있습니다. 공개된 갤러리는 전시 상세페이지의 관람 링크와 `/virtual-gallery` 목록에서 접근할 수 있으며, 개별 주소는 `/virtual-gallery/{전시 ID}`입니다.

초안 미리보기 주소는 `/virtual-gallery/{전시 ID}?preview=1`입니다. 실제 운영에서는 승인된 Google 직원 계정의 로그인 상태가 필요합니다. 로그인되지 않았다면 관리자에서 로그인한 뒤 미리보기를 다시 엽니다. 갤러리 공개와 홈페이지 슬라이드 노출은 별도 설정입니다. 홈페이지 슬라이드에 연결하려면 메인 슬라이드 관리에서 이 개별 주소를 사용합니다.

## 저장 구조와 접근 권한

실제 운영은 기존 Firebase 프로젝트 `unframe-main`과 웹 앱 `1:1003147136936:web:ae4a2bd6ec1ca8ade7179d`를 사용합니다. 설정은 `virtualGalleries/{전시 ID}`, 작품 정보는 그 아래 `artworks/{작품 ID}` 문서에 저장합니다. 갤러리는 기존 전시와 연결되며 대체 프로젝트나 앱을 만들지 않습니다.

이미지는 Cloudflare R2에 `virtualGalleries/{전시 ID}/{작품 ID}/{UUID}.{jpeg|png|webp}`의 네 구간 경로로 저장합니다. Firestore 작품 문서는 이미지 경로와 설명을 보관하고 실제 운영의 이미지 URL 필드는 비워 둡니다. 이미지 서버는 공개된 갤러리의 해당 작품 문서가 참조하는 파일만 일반 방문자에게 제공합니다. 전시와 갤러리의 공개 조건은 Firestore 규칙에서도 적용됩니다. 미게시 이미지 열람, 이미지 업로드·삭제, 갤러리와 작품 수정은 승인된 직원만 가능합니다. 직원 승인은 검증된 Google 로그인과 활성화된 `staffEmails/{이메일}` 기록으로 판단합니다.

샘플 모드는 `CONFIG.mode`가 `demo`인 경우에만 사용됩니다. 기존 프로젝트 포스터를 사용한 샘플 작품과 변경 내용은 브라우저의 로컬 저장소를 사용하며 실제 Firebase나 R2에 저장되지 않습니다. 브라우저 저장소를 지우면 샘플 변경 내용이 사라집니다. 실제 운영 전환은 빌드 설정과 운영용 권한 배포를 함께 확인해야 합니다.

## 삭제와 문제 해결

작품 삭제는 확인 후 작품 문서와 이미지 파일을 삭제하며 복구할 수 없습니다. 작품은 삭제됐지만 이미지 정리에 실패했다는 안내가 나오면 R2의 해당 경로를 별도로 정리합니다. 업로드 후 작품을 저장하지 않고 닫은 파일은 작품 문서에서 참조되지 않을 수 있으므로 저장소 정리 시 참조 여부를 확인합니다.

- 공개 링크가 열리지 않으면 전시 게시 상태와 갤러리 공개 상태를 모두 확인합니다.
- 미리보기에 변경이 없다면 공간 설정 또는 작품 저장을 완료했는지 확인합니다.
- 작품이 추가되지 않으면 공간 설정을 먼저 저장했는지, 전체 및 벽면별 수량 제한을 넘지 않았는지 확인합니다.
- 이미지 업로드 실패 시 파일 형식·크기와 직원 로그인 상태를 확인합니다.
- 운영 배포에는 Firestore 규칙과 R2 이미지 Worker의 버추얼 갤러리 지원이 함께 필요합니다. 배포 전 검증은 `site/`의 구문 검사, 관련 테스트와 사이트 빌드로 수행합니다.

## 오픈콜 단체전의 작가별 갤러리

전시 관리 목록에서 해당 전시의 **버추얼 갤러리**를 선택하면 **전시 · 작가별 갤러리** 관리 화면이 열립니다. 기존 전시 전체 공간은 그대로 유지됩니다. **작가별 갤러리 추가**에 참여 작가명과 노출 순서를 입력하면 비공개 공간이 생성됩니다. 작가 소개 페이지나 별도의 작가 계정은 생성하지 않습니다.

각 공간의 **작품 · 공간 관리**에서 작품을 추가하고 바닥·벽·조명 등의 환경을 설정합니다. 새 작품의 작가명은 해당 갤러리의 작가명으로 기본 입력됩니다. 작품명·이미지·작가명·세로와 가로 치수는 작품별로 확인합니다. 마지막 작품을 삭제하려면 먼저 갤러리를 비공개로 저장해야 합니다.

작품을 한 점 이상 저장한 뒤 **버추얼 갤러리 공개**를 선택하고 **공간 설정 저장**을 누릅니다. 연결 전시도 공개된 경우 전시 상세의 **온라인으로 전시 보기**에 자동으로 나타납니다. 작가명·갤러리 제목·노출 순서·공개 상태는 공간 설정에서 변경합니다. 공개 해제하면 방문자 목록과 공간 접근에서 제외되며, 승인된 직원은 저장된 공간을 미리 볼 수 있습니다. 갤러리에서 **갤러리 선택**을 누르면 같은 전시의 전체·작가별 공간 목록으로 돌아갑니다.

각 작가 공간은 독립된 갤러리 ID를 사용합니다. 작품 데이터는 `virtualGalleries/{galleryId}/artworks/{artId}`, 이미지는 R2 `virtualGalleries/{galleryId}/{artId}/{uuid}` 경로에 저장됩니다. 신규 작가 갤러리에는 `exhibitionId`, `artistName`, `order`를 함께 저장하며 연결 전시는 변경할 수 없습니다. 기존 전시 전체 공간은 ID 자체를 전시 ID로 해석하므로 데이터 이관이 필요 없습니다. 공개 조회는 전시 ID·공개 상태로 필터링한 뒤 화면에서 순서를 정렬합니다. 직원 두 계정의 기존 권한을 유지합니다.

메인 히어로에 작가 공간을 연결하려면 미리보기 주소의 `?preview=1`을 제외한 `/virtual-gallery/{galleryId}`를 소식·메인 노출 관리의 버추얼 갤러리 연결 주소에 사용합니다. 공개와 메인 노출은 독립적인 설정입니다. 샘플 작가 공간은 로컬 데모에만 존재하며 실제 Firestore에 생성되지 않습니다.


## 싱글룸 표현 업그레이드 (외부·실내만 적용)

현재 16×14m 방과 실측 작품 배치는 유지합니다. 창밖은 제공된 숲 WebP 뒤에 포장 바닥·콘크리트 화단·입체 식재·목재 측벽을 조합한 테라스로 바뀌었습니다. 모바일에서는 식재 수를 줄이고, 움직임 줄이기 설정에서는 잎의 미세 움직임을 멈춥니다. 외부 표시를 끄면 숲과 테라스를 생성하지 않습니다. 숲 로딩 실패 시 기존 생성 풍경을 대체로 사용합니다.

관리자 공간 설정의 **바닥 소재**에 새틴 우레탄을 추가했습니다. **조명 방식**은 전체 조명·작품 중심 조명, **천장 표현**은 일반 천장·광천장을 선택할 수 있습니다. 기존 데이터에 새 필드가 없으면 전체 조명과 일반 천장을 사용합니다. 새 공간의 기본 천장은 광천장입니다. 저장한 설정만 미리보기에 적용됩니다.

작품 형태를 **캔버스**로 선택하면 **두께 (0.5~10cm)** 및 **측면 표현 (자연색·검정·이미지 감싸기)**를 설정할 수 있습니다. 기존 캔버스는 3.5cm·자연색입니다. 작품 정면의 세로·가로(cm)는 변하지 않으며 액자와 종이에는 캔버스 옵션이 적용되지 않습니다. 작품 이미지는 실내 조명으로 색이 과도하게 변하지 않게 표시합니다.

원본 렌더링 참고 소스·설명은 `references/single-room-gallery/`, 실제 사용 텍스처는 `site/assets/virtual-textures/`에 보관합니다. 참고 패키지의 React 앱, 별도 저장 방식, 샘플 작품이나 다른 방 형태는 통합하지 않았습니다. 추가 설정은 선택 필드로 Firebase 규칙에서 검증하며 기존 전시/작가 연결과 직원 권한을 유지합니다.

전시 수정의 **저장 및 게시 → 참여 작가 · 대표작 뷰잉룸 사용**을 체크하고 저장하면 전시 소개 다음에 가로형 작품 진열대가 표시됩니다. 기존 전시는 기본적으로 꺼져 있습니다. 전시와 갤러리가 모두 공개된 작품만 가져옵니다. 작가 필터, 좌우 탐색, 작품 상세 확대, 전체 화면 관람과 해당 갤러리 연결을 제공합니다. 작품은 기존 버추얼 갤러리 작품 관리에서 수정합니다. 공개할 작품이 없으면 준비 안내를 표시합니다. 아임웹 API 동기화나 오디오 업로드는 이번 기능에 포함되지 않습니다.


## 작가 직접 업로드와 승인 (2026-10-21)

작가에게 관리자 권한을 주지 않고 작품을 직접 올리게 하는 기능입니다. 작가가 올린 내용은 승인 전까지 공개 갤러리와 분리된 `virtualSubmissions/{초대ID}`에 저장되며, 언프레임 직원이 승인해야 공개 갤러리가 됩니다.

### 작가 초대

1. `/admin` → 전시의 **버추얼 갤러리** → **작가 초대 · 심사 관리**를 엽니다.
2. 작가명은 필수, 이메일은 선택입니다. 이메일을 입력하면 그 Google 계정으로만 업로드할 수 있고, 비워두면 링크로 처음 로그인한 계정에 연결됩니다.
3. **초대 링크 만들기**를 누르면 안내문이 바로 복사됩니다. 카카오톡이나 문자에 붙여넣어 보내면 됩니다.
   - 클립보드를 쓸 수 없는 브라우저에서는 직접 복사할 수 있는 창이 뜹니다.
   - 안내문에는 링크, 기한, 절차, 그리고 "처음 로그인한 Google 계정에 권한이 연결됩니다" 안내가 들어 있습니다.
4. 초대 카드에서 할 수 있는 일: **링크 복사**, **안내문 복사**, **메일로 보내기**(이메일이 있을 때), **기한 연장**(오늘부터 10일), **초대 취소**(업로드 내용까지 삭제).

### 작가 화면 (`/artist-studio/{초대ID}`)

- **링크 첫 화면:** 계정 귀속 안내, 절차, 자동 삭제 안내, 기한이 표시됩니다. **업로드하기**를 누르면 Google 로그인 후 그 계정에 연결됩니다.
- **작품 입력 항목:** 이미지, 작품명, 세로·가로(cm), 벽면, 형태는 필수이고 제작연도, 재료, 설명, 이미지 설명은 선택입니다.
  - 공간 설정은 바닥, 벽 색, 조명, 천장만 바꿀 수 있습니다.
  - 작품 수 제한(최대 24점, 벽당 8점)과 실측 배치 검사는 관리자 화면과 같습니다.
- **3D 미리보기:** `/virtual-gallery/submission/{초대ID}`에서 볼 수 있습니다. 본인과 직원만 열 수 있습니다.
- **심사 요청 후:** 편집이 잠깁니다. **요청 취소**를 누르면 다시 고칠 수 있습니다.
- **반려되었을 때:** 반려 사유가 화면 위에 표시되고 다시 편집할 수 있습니다.
- **승인 후:** 제출 내용이 정리되므로 링크는 더 이상 열리지 않습니다. 같은 계정으로 들어오면 **내 버추얼 갤러리** 목록에서 **수정본 만들기**를 할 수 있습니다.
- **수정본:** 승인되기 전까지 기존 공개 갤러리는 그대로 유지됩니다.

### 심사

- `/admin` 첫 화면에 **작가 업로드 심사 대기 N건**이 표시됩니다.
- 심사 화면에서 작품을 확인하고 3D 미리보기를 엽니다. 수정본이면 작품마다 추가·변경·삭제 표시가 붙습니다.
- 처리 방법은 세 가지입니다.
  - **승인 후 공개**
  - **승인만:** 신규 갤러리는 비공개로 반영되고, 수정본은 기존 공개 상태를 그대로 유지합니다.
  - **반려:** 사유를 반드시 입력합니다.
- 승인하면 다음 순서로 처리됩니다.
  1. 이미지를 갤러리 경로로 복사합니다(Worker `POST /copy`, 직원 전용).
  2. 작가 갤러리(`artistEmail` 기록)를 만들거나 수정본 내용으로 교체합니다.
  3. 수정본에서 빠진 작품과 이미지를 삭제합니다.
  4. 제출 내용을 삭제합니다.
- 중간에 실패하면 제출 내용이 남아 있으므로 다시 승인하면 됩니다. 같은 결과로 완료됩니다.

### 10일 자동 삭제

- 기한은 **마지막 수정(작가 저장, 직원 기한 연장·반려) 후 10일**입니다. 기준은 서버 시각(`touchedAt`)이며 브라우저 시간과 관계없습니다.
- 기한이 지나면 Firestore 규칙과 이미지 서버가 즉시 작가 접근을 막습니다.
- 실제 삭제는 직원이 `/admin`에 들어올 때 자동으로 처리되고, "기한이 지난 작가 업로드 N건을 정리했습니다" 알림이 표시됩니다.
- 서비스 계정 키나 예약 실행은 사용하지 않습니다. 따라서 직원이 오래 접속하지 않으면 파일이 그만큼 남아 있지만, 그동안에도 아무도 볼 수 없습니다.
- 공개 중인 갤러리는 만료 대상이 아닙니다.

### 보안 요약

- **작가 권한:** 작가는 `staffEmails`에 추가되지 않습니다.
  - 자기 제출 내용만 읽고 쓸 수 있고, 다른 제출 내용 목록은 볼 수 없습니다.
  - 공개 여부와 `virtualGalleries`는 바꿀 수 없습니다.
- **제출 내용 조건:** 초대 ID는 22자 무작위 값입니다. 귀속 계정, 전시, 대상 갤러리는 처음 정해진 뒤 바뀌지 않습니다.
- **작품 저장:** 작품을 저장할 때 제출 문서의 `touchedAt`도 같은 일괄 쓰기로 갱신해야 규칙을 통과합니다.
- **이미지 서버:** 제출 경로 이미지는 직원 또는 기한 내 주인만 읽고 쓸 수 있습니다. 쓰기는 작성 중·반려 상태에서만 됩니다.
  - 제출 내용 하나당 이미지는 최대 60개까지 저장됩니다.
  - 승인된 작가는 자기 비공개 갤러리 이미지를 볼 수 있습니다(수정본 작성용).

### 배포 순서

- 운영에 반영하려면 다음을 함께 배포합니다.
  - Firestore 규칙(`site/firestore.rules`)
  - 이미지 Worker(`site/media-worker`)
  - 사이트
- 규칙 배포 전에 이 기능을 쓰면 권한 오류가 납니다.
- 규칙 에뮬레이터 테스트 실행 방법:
  1. Java를 영어 로케일로 실행합니다. 한국어 로케일에서는 에뮬레이터 내부 메시지 파일이 없어 오류가 납니다.

     `java -Duser.language=en -jar ~/.cache/firebase/emulators/cloud-firestore-emulator-v1.22.0.jar --host 127.0.0.1 --port 8087`
  2. 다음 명령을 실행합니다.

     `FIRESTORE_EMULATOR_HOST=127.0.0.1:8087 node scripts/test-firestore-rules.mjs`

## 관람 개선 (2026-10-21)

- **화면 정리:** 입장하면 제목 카드가 작아지고 버튼은 **메뉴** 하나로 묶입니다. 4초 동안 조작이 없으면 화면 요소가 흐려지고, 움직이면 다시 나타납니다.
- **안내 문구:** 터치 기기에서는 키보드 안내 대신 드래그·버튼 안내를 보여줍니다.
- **벽 캡션:** 글자를 키우고 작품 옆 8cm 위치로 옮겼습니다.
- **가이드 투어:** 상세 창 없이 작품 앞에 서서 감상합니다. 하단 막대에 `3 / 12` 진행 표시, 이전, 상세 보기, 다음, 투어 종료가 있고, 마지막 작품에서 끝납니다.
- **작품 주소:** `#art-{작품ID}`로 열면 입장 시 그 작품 앞으로 이동합니다. 상세 창은 방문 기록에 남아 뒤로가기로 닫힙니다. 작품 공유 카드의 주소도 이 형식입니다.
- **메뉴의 벽 이동:** 전면, 좌측, 우측 벽으로 바로 이동합니다.
- **로딩 진행률:** 입장 화면에 진행률이 표시되고, 다 불러오면 입장 버튼이 켜집니다. 늦어져도 최대 10초 뒤에는 입장할 수 있습니다.
- **이미지 확대:** 상세 이미지를 누르면 2배로 확대되고, 포인터를 움직여 살펴볼 수 있습니다.
- **기기별 화질:** 기기에 따라 저·중·고 화질을 자동으로 고릅니다(해상도 배율, 그림자, 식재 수). 입장 후 3초 평균이 40fps보다 낮으면 한 단계 낮춥니다.
- **Three.js:** r128을 유지했습니다. 최신 버전 전환은 별도 작업으로 남깁니다. 전역(UMD) 빌드가 없어지고 조명 단위가 바뀌어 전체 재조정과 화면 비교가 필요하기 때문입니다.
- **작품 오디오 해설:** 포함하지 않았습니다(별도 작업).

## 추가 개선 (2026-10-21, 2차)

- **벽 색상:** 직접 고르는 색상표 대신 7가지 갤러리 색 중에서 고릅니다. 관리자 화면과 작가 화면 모두 같습니다.
  - 색상: 웜 화이트, 퓨어 화이트, 라이트 그레이, 웜 그레이, 차콜, 딥 그린, 딥 네이비.
  - 기존에 다른 색을 쓰던 갤러리는 "기존 색상"으로 그대로 유지됩니다.
- **작가 소개:** 작가가 업로드 화면에서 600자 이내로 입력합니다(`artistNote`, 선택 항목).
  - 심사 화면에 함께 표시되고, 관리자도 작가 갤러리의 공간 설정에서 고칠 수 있습니다.
  - Firestore 규칙에 이 필드가 추가되었으므로 규칙을 다시 배포해야 합니다.
- **입장 정보창:** 처음 들어갈 때 전시명, 기간, 장소, 전시 소개(관리자 전시 정보)와 작가명, 작가 소개를 보여줍니다. 입장 후에는 **메뉴 → 전시 정보**로 다시 볼 수 있습니다.
- **입장 시점:** 처음 들어갈 때와 **입구로** 버튼을 눌렀을 때 모두 정면 벽 가운데를 바라봅니다.
- **실시간 3D 미리보기:** 작가 업로드 화면의 공간 설정 옆에 붙어 있습니다.
  - 바닥과 벽 색은 즉시 바뀝니다.
  - 조명과 천장은 미리보기를 다시 불러옵니다.
  - 미리보기에서 바꾼 것은 **설정 저장**을 눌러야 저장됩니다.
  - 이 미리보기를 위해 사이트 응답 헤더 `X-Frame-Options`를 `DENY`에서 `SAMEORIGIN`으로 바꿨습니다. 같은 사이트 안에서만 페이지를 화면 속에 넣을 수 있고, 다른 사이트에서는 여전히 넣을 수 없습니다.
- **전시 상세페이지:** "참여 작가의 온라인 공간" 카드 목록으로 바뀌었습니다.
  - 카드마다 대표 작품, 작가명, 작가 소개 두 줄, 작품 수가 들어갑니다.
  - 전시 전체 갤러리는 위쪽에 넓은 카드로 표시됩니다.

## 관리자 사전 업로드 (2026-10-22)

초대 카드의 **작품 미리 올리기**를 누르면 작가 업로드 화면이 관리자 모드(`/artist-studio/{초대ID}?as=staff`)로 열립니다. 관리자가 작품을 미리 올려두면 작가는 링크를 열었을 때 그 작품을 예시로 참고할 수 있고, 등록하는 수고도 줄어듭니다.

- **화면:** 입력 칸, 3D 미리보기, 공간 설정이 작가 화면과 같습니다. 관리자 모드에는 심사 요청 버튼 대신 **관리자로 돌아가기**가 있습니다.
- **수정할 수 있는 기간:** 초대됨, 작성 중, 반려됨 상태에서 가능합니다. 작가가 심사를 요청한 뒤에는 관리자도 수정할 수 없습니다. 관리자가 저장해도 10일 기한이 다시 시작됩니다.
- **작가가 보는 화면:** 링크를 열면 미리 올라간 작품이 목록에 있고, 처음 한 번 "언프레임이 작품 N점을 미리 등록해 두었습니다"라는 안내가 나옵니다. 작품에 별도 표시는 없고, 작가가 자유롭게 고치거나 지울 수 있습니다.
- **보안:** Firestore 규칙에 관리자의 제출함 작품·공간 설정 쓰기 권한을 추가했습니다. 기존 작가 권한과 다른 계정 차단은 그대로입니다.
