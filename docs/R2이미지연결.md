# R2 이미지 연결

이미지는 Cloudflare R2 `unframe-media`에 저장하고 전시 정보와 관리자 승인 목록은 기존 Firebase `unframe-main`에 저장합니다. Firebase Storage와 서비스 계정 키는 사용하지 않습니다.

## 승인 목록

`staffEmails/{Google 이메일}` 문서의 `email`과 `active: true`를 확인합니다. 본인 `gallerykuns@gmail.com`, 직원 `sylove887@gmail.com` 문서를 생성했습니다. 최초 Google 로그인부터 사용할 수 있습니다. 승인 목록은 클라이언트에서 생성·수정·삭제할 수 없습니다. 해당 문서의 active를 false로 변경하면 다음 서버 요청부터 업로드 권한을 철회합니다.

## 이미지 서버

`site/media-worker/index.mjs` / `wrangler.jsonc`에 배포 코드를 관리합니다. Worker 이름과 R2 버킷 이름은 모두 `unframe-media`입니다. JWT의 서명, 대상 프로젝트, 만료, Google 로그인 및 이메일 확인 여부를 검사한 뒤 Firestore 승인 목록을 읽습니다.

- 관리자: 업로드, 삭제, 저장 전 이미지 및 임시 저장 전시 열람 가능.
- 방문자: 게시된 전시의 대표 이미지 또는 갤러리에 실제 연결된 파일만 열람 가능.
- JPEG·PNG·WebP, 최대 10MB, 서버에서 파일 헤더 검사.
- 이미지 응답 및 전시 게시 여부는 캐시하지 않습니다. 게시를 취소하면 다음 요청부터 차단됩니다. 이미 방문자에게 전달된 파일은 회수할 수 없습니다.
- 버킷의 공개 접근(r2.dev/공개 도메인)은 켜지 않습니다.
- 허용 사이트: unframe-main.netlify.app, unframe.kr, www.unframe.kr, localhost:4173, 127.0.0.1:4173.
- Worker 배포에는 Workers 수정 권한이 필요하며 R2 전용 OAuth 권한만으로는 배포되지 않습니다.

배포한 서버는 https://unframe-media.gallerykuns.workers.dev 입니다. Worker HTTPS origin을 `site/config.js`의 mediaBaseUrl 기본값에 반영합니다. Netlify `UNFRAME_MEDIA_BASE_URL` 값으로 덮어쓸 수 있습니다. Firebase SDK 공개 환경변수는 기존 값을 유지하며 FIREBASE_STORAGE_BUCKET은 더 이상 필수가 아닙니다.

## 검증

사이트 문법 검사, 19개 테스트, 사이트 빌드, Worker 배포 전 패키징 검사 통과. 테스트는 Node 환경에서 R2와 Firestore 응답을 대체하며 공개/임시 전시, 승인/미승인 계정, 위조·만료 JWT, 용량과 파일 형식, CORS를 확인합니다. 실제 로그인·업로드 검증은 별도로 필요합니다. Java가 없어 Firestore 에뮬레이터 접근 시나리오를 실행하지 않았으며 규칙 문법 검증 및 실제 배포는 성공했습니다.
