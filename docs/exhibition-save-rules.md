# 전시 저장 오류 수정

2026-10-13, 기존 `unframe-main`의 `(default)` Standard Firestore.

`Missing or insufficient permissions`는 계정 승인 누락이 아니라 기존 사진 검증이 Firestore의 요청당 1,000개 표현식 한도를 초과해서 발생했다. 기존 규칙으로 대표 이미지만 있는 등록도 에뮬레이터에서 동일하게 실패했다.

관리자 승인 방식은 유지한다. 확인된 Google 로그인과 활성 `staffEmails` 문서가 일치해야 등록·수정·삭제가 가능하다. 공개 사용자는 게시된 전시만 읽으며, 승인 문서는 클라이언트에서 생성·수정할 수 없다.

## 사진 저장 형식

화면에서는 기존 `{url,path,alt,caption}` 이미지 객체를 그대로 사용한다. 실제 Firebase 저장 때에만 `gallery-codec.js`가 사진을 `path + US + alt + US + caption` 문자열 목록으로 직렬화한다. 규칙은 목록을 서로 다른 RS/GS 구분자로 연결해 두 번 검사한다. 한 항목에 구분자를 넣어 검사 경계를 우회할 수 없으며 사진은 최대 30장, 설명 1,000자, 캡션 2,000자로 제한된다. 입력된 예약 제어 문자 U+001D–U+001F는 공백으로 정규화하며 일반 줄바꿈·한국어·기호는 유지한다.

기존 사진 객체 목록도 읽을 수 있다. 기존 전시를 새 사이트에서 저장하면 새 형식으로 저장하며, 데모 모드는 기존 객체 형식과 브라우저 저장을 유지한다. 서버용 인증키나 공개 권한 확대는 사용하지 않는다.

R2 서버는 기존 객체 목록과 새 문자열 목록 모두에서 실제 참조 경로를 확인한다. 공개 이미지는 게시된 전시에 참조된 파일만 제공한다.

## 검증과 배포

규칙 검사는 실제 Firestore 에뮬레이터의 생성·수정 요청으로 실행한다. 웹 테스트는 인코딩 왕복, 기존 데이터 호환, 이미지 참조 권한을 확인한다. 운영 데이터에 테스트 전시를 등록하지 않는다.

최종 검증: 에뮬레이터 138개 검사, 웹·이미지 서버 단위 테스트 28개, JavaScript 구문 검사와 사이트 빌드 통과. 에뮬레이터가 로컬에서 실행 중이면 `FIRESTORE_EMULATOR_HOST=127.0.0.1:8087 node site/scripts/test-firestore-rules.mjs`로 회귀 검사를 실행한다. 테스트는 `demo-unframe-rules` 프로젝트만 사용하며 운영 데이터를 만지지 않는다.

배포 순서는 이전 형식도 지원하는 R2 Worker, Firestore 규칙, Netlify 사이트 순서다. 수정 전 배포 규칙은 `references/firebase-firestore-before-exhibition-save-fix.rules`에 보존했다.

Firestore 운영 규칙 배포 성공 후 새 규칙을 다시 조회해 확인했다. R2 Worker 버전은 `22284128-90de-4ac7-977c-7a4b800ffd46`이며 `/health` 응답도 정상이다.
